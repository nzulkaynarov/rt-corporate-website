# SEO-правила для контента

Сайт сам генерирует canonical, hreflang (ru/uz/en), sitemap, Open Graph и schema.org
(Product, Service, BlogPosting, BreadcrumbList) из полей записи. Задача автора — хорошие тексты
и поля, перечисленные ниже. Работаем под Google и Яндекс; основной рынок — Узбекистан.

## 1. Под какие запросы пишем

* Коммерческие: «<изделие> купить Ташкент», «<изделие> <модель> цена», «поставка <изделие>
  Узбекистан», «запчасти для вагонов Ташкент», «импорт оборудования под ключ DDP».
* Информационные (блог): «как рассчитать таможенную стоимость…», «ТН ВЭД для…», «ГОСТ на…»,
  «чем отличается…».
* На каждом языке — свои формулировки (не перевод ключей!): UZ — «… sotib olish Toshkent»,
  «… narxi», EN — «… supplier Uzbekistan», «… Tashkent».
* Без данных SEO-инструментов (Ahrefs/Similarweb/Wordstat) не придумывайте частотность; выбирайте
  естественные формулировки покупателя.

## 2. Заголовок (title) и описание (description)

* Поля `seoTitle[_uz|_en]` и `seoDescription[_uz|_en]` **необязательны**. Если пусты, сайт строит:
  title = `<название> | RailTech` (товар: `<название> (<SKU>) | RailTech`), description = `summary` /
  `subtitle` / шаблон товара из `seo.json`. Заполняйте их, когда автоматический вариант длиннее
  лимита или не содержит главный запрос.
* **Title:** ≤ 60 знаков, главный запрос в начале, уникален на сайте, без КАПСА и «!».
* **Description:** 70–160 знаков, что это + выгода/условие (наличие, НДС, сроки) + место (Ташкент).
* `summary` (услуги, статьи) — 70–300 знаков, это и подзаголовок, и описание для поиска.
* Если заполняете RU — заполните UZ и EN (иначе ошибка проверки).

## 3. URL (slug)

* Имя файла = URL: латиница в нижнем регистре, цифры, дефисы; 2–6 слов; без дат и стоп-слов.
  Товар — `sku` в нижнем регистре (`rt-rs-120.md`). Статья — суть запроса на английском/транслите
  (`landed-cost-ddp-tashkent.md`).
* Опубликованный slug **не меняется** (сломает ссылки и индекс). Нужна замена — отдельная задача.

## 4. Заголовки, текст, изображения

* H1 страницы — это `title`. В Markdown начинайте с `###`; структура логичная, по одной мысли на
  раздел, запросы — естественно (без повторов ради ключа).
* Первые 1–2 предложения содержат главный запрос и ответ «что это и для кого».
* Изображения: реальные фото, осмысленное имя файла (`rt-rs-120-bogie-side.jpg`); alt формирует
  сайт из названия — поэтому название должно быть описательным.
* Не дублируйте один и тот же текст в нескольких записях — поисковики склеят страницы.

## 5. Внутренние ссылки

* В каждой статье — 2–5 ссылок на товары/услуги/проекты сайта, в каждой услуге — на 1–3 статьи или
  товара. Формат Markdown: `[колёсные пары](/catalog/rt-rs-102/)` — маршрут без языка и без домена.
* Анкор описывает цель («расчёт Landed Cost»), не «здесь» / «подробнее».

## 6. Чек-лист перед PR

- [ ] title уникален и ≤ 60, description 70–160 (или поля пусты и автовариант в норме)
- [ ] главный запрос в title, первом абзаце и одном подзаголовке, на всех трёх языках — своими словами
- [ ] slug по правилам, не менялся у существующих записей
- [ ] 2–5 внутренних ссылок (для статей)
- [ ] `npm run build` без предупреждений `check-build` по вашим страницам
