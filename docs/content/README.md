# Контент RailTech: правила для ИИ-агентов и редакторов

Этот раздел — единый регламент пополнения сайта (товары, услуги, проекты, статьи, тексты страниц)
на трёх языках. Он обязателен для любых ИИ-агентов (Claude Code, Cursor, Copilot, Codex…) и людей.

| Документ | О чём |
|---|---|
| [STYLE_GUIDE.md](./STYLE_GUIDE.md) | Тон, факты, форматы, правила UZ/EN, что запрещено |
| [GLOSSARY.md](./GLOSSARY.md) | Обязательная терминология RU / UZ / EN (+ запрещённые варианты) |
| [SEO.md](./SEO.md) | Заголовки, описания, ключевые слова, URL, alt, перелинковка |
| [templates/](./templates/) | Шаблоны новых записей: товар, услуга, проект, статья; `catalog-import.csv` — таблица для пакетного заведения номенклатуры |
| [CONTENT_PLAN.md](./CONTENT_PLAN.md) | Текущий контент-план: волны работ, темы статей с запросами, что нужно от владельца |
| `npm run check:content` | Автоматическая проверка контента (обязательна перед PR) |

## 1. Где что лежит

| Тип контента | Файл | URL на сайте | Скил Claude Code |
|---|---|---|---|
| Товар каталога | `src/content/catalog/<sku-в-нижнем-регистре>.md` | `/catalog/<slug>/`, `/uz/…`, `/en/…` | `add-product` |
| Услуга | `src/content/services/<slug>.md` | `/services/<slug>/` | `add-service` |
| Проект / кейс | `src/content/projects/<slug>.md` | `/projects/<slug>/` | `add-project` |
| Статья блога | `src/content/blog/<slug>.md` | `/blog/<slug>/` | `write-blog-post` |
| Тексты страниц, реквизиты, меню | `src/data/cms/{global,home,about,contacts,pages,legal}.json` | все страницы | `edit-site-texts` |
| SEO статических страниц | `src/data/cms/seo.json` | все страницы | `edit-site-texts` |
| Кнопки и подписи интерфейса | `src/data/cms/ui/*.json` | все страницы | `edit-site-texts` |
| Фото и файлы | `public/images/<catalog|services|projects|blog>/`, `public/docs/` | — | — |

Схема полей — `src/content/config.ts` (что сайт принимает) и `public/admin/config.yml` (что видит
редактор в /admin). Они должны совпадать: новое поле без описания в `config.yml` **будет удалено**
при первом сохранении записи из админки (сборка это проверяет).

## 2. Языковая модель (как устроены переводы)

* Одна запись = один файл, все три языка внутри: поле `title` — русский (основной),
  `title_uz` — узбекский (латиница), `title_en` — английский. Так для **каждого** текстового поля,
  в т. ч. внутри списков (`attributes[].label_uz`, `steps[].text_en`…).
* Основной текст статьи/товара: русский — Markdown под front matter; узбекский и английский —
  поля `body_uz` и `body_en` (Markdown, многострочная строка YAML `|`).
* Сайт показывает русский, если перевод пуст. Для агентов это **ошибка**: агент обязан заполнить
  все три языка. `check:content` падает на любом непереведённом поле.
* Каждый язык — отдельный URL (`/…`, `/uz/…`, `/en/…`). Ссылки внутри текстов — относительные
  маршруты без языка (`/catalog/rt-saf-001/`); локализацию делает сайт.

## 3. Процесс (обязательный порядок)

1. **Бриф.** Задача приходит issue «Новый контент» (`.github/ISSUE_TEMPLATE/content-request.yml`)
   или сообщением. Агент выписывает: что публикуем, факты и цифры, источники, фото/документы.
   Чего не хватает — спрашивает, а не выдумывает (см. STYLE_GUIDE §2).
2. **Ветка.** `git switch -c content/<тип>-<slug>` от свежего `main`. Никогда не коммитить в `main`.
3. **Черновик RU** по шаблону из `templates/` и скилу нужного типа.
4. **Переводы UZ и EN** — по GLOSSARY и STYLE_GUIDE §4. Не машинный подстрочник: тот же смысл,
   естественная фраза для носителя.
5. **SEO** — по SEO.md (заголовок, описание, alt, внутренние ссылки).
6. **Медиа** — реальные фото в `public/images/...` в **JPG или PNG** (≤ 1600 px по длинной стороне,
   латинские имена файлов). WebP-версии 480/800/1200 px сайт создаёт сам при сборке — сами WebP
   не загружайте и не коммитьте. Нет фото — не ставим чужое, пишем в PR.
7. **Проверка:** `npm run check:content -- --strict` → `npm run build`
   (валидатор CMS, `astro check`, аудит SEO/i18n). Всё зелёное — иначе исправить.
8. **PR** в `main` по шаблону `.github/pull_request_template.md`: что добавлено, источники фактов,
   открытые вопросы. Проверку делает человек (и/или агент `content-reviewer`). Мёрж = публикация.

## 4. Чего агенту делать нельзя

* Публиковать в `main` напрямую, делать `git push --force`, мёржить свои PR.
* Менять код (`src/pages`, `src/components`, `src/layouts`, `src/utils`, `src/i18n`, `scripts`,
  `astro.config.mjs`) в контентной задаче. Нужна правка кода — отдельная задача.
* Менять реквизиты компании (ИНН, банк, адреса, телефоны) без явного указания человека в брифе.
* Придумывать цены, наличие, сертификаты, клиентов, цифры, отзывы, сроки (STYLE_GUIDE §2).
* Удалять или переименовывать существующие записи и ключи `ui/*.json` (ломает URL и сборку) —
  только по прямой просьбе, с редиректом/заменой.
* Копировать тексты и фото с сайтов конкурентов и производителей без права использования.
