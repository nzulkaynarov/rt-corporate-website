# Контент-план RailTech (старт: ноябрь 2026)

Рабочий план наполнения сайта на трёх языках. Ведут ИИ-агенты по правилам `docs/content/`,
проверяет и мёржит человек. Статус задач — в issues «Новый контент» с меткой `content`.

**Принятые решения**
* Цены на сайте не публикуются — только «Цена по запросу» и запрос КП (STYLE_GUIDE §2).
* Источник номенклатуры — прайс-лист / номенклатура компании (без цен). Характеристики — из прайса и
  с сайтов заводов-производителей. Тексты с сайтов производителей **не копируем**: пересказываем своими
  словами, параметры сверяем, ссылку на источник указываем в PR. Фото производителей — только
  с их разрешения (запрос дистрибьютору), иначе — свои фото со склада.

## 1. Где мы сейчас (аудит 03.11.2026)

| Раздел | Сейчас | Проблема | Действие |
|---|---|---|---|
| Каталог | 10 товаров, 5 категорий | фото — общие заглушки; ссылки на паспорта пустые; тексты 110–140 знаков | Волна 1: дополнить, затем расширять из прайса |
| Услуги | 4 страницы | тексты короткие, без кейсов и FAQ | Волна 3 |
| Проекты | 5 кейсов | 170–250 знаков, нет цифр и фото | Волна 3: только по реальным данным |
| Блог | 4 статьи | 3 из 4 короче 1200 знаков; нет статей под коммерческие запросы | Волна 2 |
| Тексты страниц | заполнены на 3 языках | `shortName` без UZ/EN | мелкая правка |

Рынок: специализированных онлайн-каталогов ЖД-запчастей в Узбекистане почти нет — выдача по
«запчасти для вагонов Ташкент» состоит из справочников автозапчастей. Запросы с названием изделия и
модели («колёсная пара РУ1Ш-957-Г», «автосцепка СА-3», «колодка тормозная композиционная») —
основной шанс быстро занять выдачу. Заказчики: УТЙ (закупки через railway.uz и dxarid.uzex.uz),
промышленные предприятия с подъездными путями, ремонтные депо, подрядчики.

## 2. Волны работ

### Волна 1 — каталог (недели 1–3)

1. **Номенклатура из прайса.** Владелец передаёт прайс (Excel/CSV в любом виде) — агент приводит его
   к таблице `docs/content/templates/catalog-import.csv` и согласует с человеком список позиций
   и категорий. Цены из прайса не используются.
2. **Существующие 10 товаров:** реальные фото и паспорта (или удалить ссылки-заглушки), описание
   400–800 знаков (назначение → конструкция → параметры → комплектность), характеристики 5–10 строк.
3. **Новые позиции** — партиями по 10–20 (скил `add-product`, агент `content-writer`), каждая партия —
   отдельный PR. Приоритет: что есть на складе (`В наличии`), затем ходовое `Под заказ`.
4. **Категории.** Сейчас 5: подвижной состав, СЦБ и автоматика, путевое хозяйство, КИП и диагностика,
   энергетика. Новые категории — только после согласования (они попадают в фильтр каталога).
5. Для разработки (не контент): отдельные посадочные страницы категорий
   (`/catalog/<категория>/`) с текстом и мета-тегами — сильный SEO-рычаг под запросы
   «тормозные колодки купить Ташкент». Поставить задачу, когда в категориях будет ≥ 5 товаров.

### Волна 2 — блог под поисковые запросы (недели 2–8, 1–2 статьи в неделю)

Каждая статья: 3000–6000 знаков RU, полные UZ/EN, 2–5 ссылок на товары/услуги, источники в PR.
Ставки, сроки и требования — **только из официальных источников** (lex.uz, customs.uz, standart.uz,
railway.uz, тексты ГОСТ) с датой актуальности в тексте. Агрегаторы тарифов не годятся.

### Волна 3 — услуги и проекты (по мере получения данных)

* **Услуги:** для каждой — что входит, этапы, сроки, документы, FAQ (5–7 вопросов, schema FAQPage
  уже поддерживается на «О компании» — для услуг это задача разработки), 1–2 ссылки на кейсы.
* **Проекты:** только реальные: задача → решение → результат в цифрах, фото, разрешение клиента на
  упоминание. Без данных кейс не расширяем.

## 3. Что нужно от владельца

| Что | Для чего | Формат |
|---|---|---|
| Прайс / номенклатура | Волна 1 | Excel/CSV, любой вид; цены можно не удалять — агент их не переносит |
| Ссылки на сайты производителей | характеристики, ГОСТ | список ссылок рядом с позициями |
| Фото со склада | карточки товаров | JPG, ≥ 1200 px по ширине, по 1–3 на позицию, имя = артикул |
| Паспорта / сертификаты PDF | блок «Документы» | PDF, имя = артикул |
| Решения по категориям | фильтр каталога | список |
| Факты для услуг и кейсов | Волна 3 | ответы на вопросы агента в issue |

## 4. Ритм и контроль

* Партия товаров или статья = отдельный PR с пометкой источников и открытых вопросов; мёрж = публикация.
* Перед PR: `npm run check:content -- --strict` и `npm run build` (агент делает сам), ревью — человек
  или агент `content-reviewer`.
* После переезда на railtech.uz: подключить Google Search Console и Яндекс Вебмастер, отправить
  sitemap; ежемесячно смотреть показы/клики по страницам каталога и статьям и обновлять план.
