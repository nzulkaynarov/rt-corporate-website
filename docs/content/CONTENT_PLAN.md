# Контент-план RailTech (v2, с ноября 2026)

Материалы готовят ИИ-агенты по правилам `docs/content/`, проверяет и мёржит человек. Задачи заводятся как
issues «Новый контент для сайта» с меткой `content`.

## Принятые решения

- Сайт рассказывает о компании и её возможностях и приглашает к работе через Кабинет. Каталог, цены и сделки ведутся в Кабинете (ARCHITECTURE.md §1).
- Позиционирование не привязано к отрасли: RailTech работает с любыми предприятиями. Отрасль упоминается только в фактах о партнёре или событии.
- Этап RU-first: сначала владелец принимает русскую версию, потом идёт один проход перевода UZ и EN.
- Дилерский статус ставится только по документу производителя. Основание на сайте не публикуется.

## План

### Шаг 1. Одобрение RU (текущий)
1. Владелец читает русскую версию: главную, услуги, статьи о партнёрах, новости, контакты, юридические страницы.
2. Правки идут отдельными PR (`edit-site-texts`, `add-service`, `write-news`).
3. Итог шага: владелец пишет «RU принят» и сам переключает `src/data/content-stage.json → ruOnly: false`.

### Шаг 2. Проход перевода (после шага 1)
1. Скил `translate-content` / агент `content-translator`: весь сайт на UZ и EN по GLOSSARY, отдельные PR по разделам.
2. Строки глоссария с пометкой «проверить» подтверждает носитель.
3. После мёржа страницы UZ/EN откроются для индексации, их нужно проверить в Search Console.

### Постоянно: партнёры, кейсы, фото
- **Статьи о партнёрах:** новый производитель добавляется только с решением владельца и источниками (скил `add-partner`).
- **Проекты с цифрами:** задача → решение → результат. Цифры и имя клиента пишем только с подтверждения и разрешения.
  Каждый проект получает ссылку из своей услуги.
- **Фото:** свои фото с событий, со склада и с объектов, либо с разрешения организатора. Обложки 16:10, JPG, ≥ 1200 px по ширине.

### Новости: ритм
- 2–4 материала в месяц: события компании и партнёров, проекты, практические статьи для заказчиков и партнёров
  (поставка и документы, выход производителя на рынок Узбекистана, локализация).
- Каждое событие публикуется в течение недели. Нормативка берётся только из официальных источников с датой актуальности.

## Что нужно от владельца

| Что | Для чего |
|---|---|
| Одобрение RU-версии и переключение `ruOnly` | старт перевода |
| Факты и разрешения клиентов для кейсов | проекты с цифрами |
| Фото с событий, склада, объектов | обложки новостей и проектов |
| Документы о статусе от производителей (внутренне, не для публикации) | статус `dealer` |
| Подтверждение цифр в `company.json → metrics` | главная, «О компании» |

## Контроль

- Один материал или одна правка разделов идёт отдельным PR с источниками и открытыми вопросами. Мёрж означает публикацию.
- Перед PR: `make check`. Ревью делает человек или агент `content-reviewer`.
- После переезда на railtech.uz подключаем Google Search Console и Яндекс Вебмастер, раз в месяц смотрим показы и клики и обновляем план.
