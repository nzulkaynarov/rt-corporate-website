## Шаг 1. Цветовая схема и типографика

### 1.1. Текущее состояние

Цветовая схема `railtech.css` использует:
- **Primary:** Orange (Tailwind orange scale, акцент `#f97316`)
- **Neutral:** Zinc (тёмный корпоративный фон)
- **Secondary:** Slate (второстепенные поверхности)

### 1.2. Диагноз

| Проблема | Влияние | Тип |
|----------|---------|-----|
| Оранжевый акцент (#f97316) ассоциируется с ритейлом, стройкой, фудтехом — не с высокотехнологичной промышленностью | Позиционирование бренда не считывается как «железнодорожные технологии» | 🔴 Критическая |
| `primary-400` на тёмном фоне даёт контраст 3.42:1 (WCAG AA fail) — выявлено в WCAG-аудите | Часть текста на чипах нечитаема | 🔴 Критическая |
| Нет secondary-акцента — весь цвет на одном оранжевом, визуал «плоский» | Отсутствие глубины и визуальной иерархии | 🟡 Значительная |
| Нейтральные Zinc — слишком тёплые для «стальной» эстетики | Не соответствует целевому образу «сталь + технологии» | 🟡 Значительная |
| Системные шрифты (ui-sans-serif) — безликие, не задают характер | Сайт визуально не отличается от дефолтного Blowfish | 🟢 Рекомендация |

### 1.3. Рекомендации

#### Новая цветовая палитра: «Steel Blue + Electric Cyan»

Предлагаемая концепция: глубокий стальной синий как основа (ассоциация: железная дорога, сталь, промышленная надёжность) + электрический циан как технологичный акцент (ассоциация: высокие технологии, цифровизация, будущее).

  --color-primary-200: 191, 219, 254;
  --color-primary-300: 147, 197, 253;

**Обоснование:**
- `primary-400` (#60a5fa) на `neutral-900` (#0f172a) даёт контраст **8.26:1** — WCAG AAA pass

- Slate neutrals создают «стальной» холодный тон вместо тёплого Zinc
- Secondary cyan (#22d3ee) добавляет «электрическую» технологичность для акцентных элементов
- Палитра профессионально ассоциируется с тяжёлой промышленностью и технологиями (аналоги: Siemens, Alstom, Knorr-Bremse)

#### Типографика

Blowfish использует системные шрифты (`ui-sans-serif, system-ui`). Для корпоративного B2B-сайта это приемлемо, но можно усилить «инженерную» эстетику через `extend-head.html`:

**Рекомендация:** Подключить **Inter** (гротеск с техническим характером, идеальная разборчивость) через Google Fonts в `extend-head.html`, затем переопределить CSS-переменную `--font-sans` в `railtech.css`:

```css
:root {
  /* ... color tokens ... */
  --font-sans: 'Inter', ui-sans-serif, system-ui, sans-serif;
}
```

И в `extend-head.html`:
```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap" rel="stylesheet">
```

**Альтернатива (без внешних зависимостей):** оставить системные шрифты — на большинстве ОС это будет SF Pro / Segoe UI / Roboto, которые достаточно нейтральны.

## Шаг 2. Главная страница

### 2.1. Текущее состояние

Структура кастомной homepage (`layouts/partials/home/custom.html`):
1. Hero: чипы + заголовок + подзаголовок + 2 CTA-кнопки
2. Stats: 4 счётчика в `<dl>` grid
3. Topic Tags: 5 тегов-чипов
4. Services preview: 2x2 карточки
5. Advantages: 4 карточки с иконками
6. Platform CTA: текст + кнопка
7. Partners: grid текстовых имён (без логотипов)
8. FAQ: 5 вопросов-ответов
9. Final CTA: заголовок + 2 кнопки

### 2.2. Диагноз

| Проблема | Влияние | Тип |
|----------|---------|-----|
| **Hero без визуала** — чисто текстовый, нет фонового изображения или графики | Нет wow-эффекта, выглядит как шаблон | 🔴 Критическая |
| **Дублирование CTA** — Hero и Final CTA идентичны (те же кнопки, тот же паттерн) | Визуальная монотонность, размывание конверсии | 🟡 Значительная |
| **Partners без логотипов** — все 8 партнёров отображаются как текст в огромных пустых карточках | Секция выглядит незавершённой и непрофессиональной, не считывается grid `sm:grid-cols-4` — показывает по 1 в колонку из-за отсутствия логотипов | 🔴 Критическая |
| **Stats идут вертикально на десктопе** — `grid-cols-2 sm:grid-cols-4`, но визуально из-за крупных чисел выглядит вертикально-центрированным | Теряется эффект «доски показателей» | 🟢 Незначительная |
| **Topic Tags секция** между Stats и Services — неочевидное назначение, выглядит как «потерянная» навигация | Прерывает повествование homepage | 🟡 Значительная |
| **FAQ без интерактивности** — все ответы открыты, длинный scroll | На мобильном занимает ~5 экранов, пользователь теряет контекст | 🟡 Значительная |
| **Нет секции «О компании» / social proof** на homepage | Нет доверительного блока: ни миссии, ни «почему мы», ни кейс-стори | 🟡 Значительная |
| **Services карточки без иконок** — хотя в frontmatter есть `icon: /img/icons/supply.svg` | Визуально однообразные прямоугольники текста | 🟡 Значительная |

### 2.3. Рекомендации

#### Hero: «background» heroStyle + hero-изображение

Переключить homepage на использование Blowfish hero с фоновым изображением. В `_index.md` (все языки):

```yaml
---
title: "RailTech"
showHero: true
heroStyle: "background"  # Blowfish встроенный — fullwidth background с blur-overlay
---
```

Подготовить hero-изображение (рекомендуемый размер: 1920x1080px):
- Вариант A: фото современного локомотива / рельсового оборудования в цехе
- Вариант B: абстрактное изображение стальных конструкций / рельсов (futuristic feel)
- Поместить как `content/ru/background.jpg` (page bundle) или `static/img/hero-bg.jpg` + `featureimage` в frontmatter

**Важно:** При `heroStyle: "background"` Blowfish сам отрисует полноширинный фон с blur-overlay. Основной текст Hero останется в `custom.html`, но теперь он будет на фоне изображения.

Альтернативный подход (без изменения homepage layout): добавить hero-изображение как CSS-градиент прямо в custom.html через Tailwind-классы — но это выходит за рамки «только нативные инструменты». Поэтому рекомендуется подход через Blowfish heroStyle.

#### Секция Topic Tags → удалить или перенести

Topic tags («Технический консалтинг», «Таможенное оформление» и т.д.) — эта секция не несёт конверсионной ценности и прерывает повествование. Рекомендации:
- **Удалить** из homepage и использовать эти ключевые слова как `tags` в контенте (для SEO)
- **Или** объединить с hero-чипами, заменив ими текущие 3 chip'а

#### FAQ → accordion shortcode

Blowfish имеет встроенный `accordion` / `accordionItem` shortcode. Рекомендация — перенести FAQ из `custom.html` в контент `_index.md` с использованием shortcode:

```markdown
## Частые вопросы

{{</* accordion */>}}
{{</* accordionItem title="Как оформить заявку на КП?" */>}}
Зарегистрируйтесь в личном кабинете...
{{</* /accordionItem */>}}
{{</* accordionItem title="Работаете ли вы с нерезидентами?" */>}}
Да, мы сотрудничаем...
{{</* /accordionItem */>}}
{{</* /accordion */>}}
```

Это даёт: сворачиваемые ответы, нативная анимация, WCAG-совместимость из коробки, мобильная оптимизация.

#### Partners → загрузить логотипы

Текстовые имена партнёров в пустых карточках 80px высоты — главный визуальный «провал» homepage. Необходимо:
1. Собрать SVG/PNG логотипы (САУТ, НИИАС, РЖД, ЭЛТЕЗА, Siemens, Knorr-Bremse, Alstom, Bombardier)
2. Поместить в `static/img/partners/`
3. Обновить `data/company.yaml` с путями к логотипам
4. Шаблон уже поддерживает `{{ if .logo }}` — код готов, нужны файлы

#### Services карточки → добавить иконки

Frontmatter уже содержит `icon: /img/icons/supply.svg`, но шаблон не использует иконки. Рекомендация: в `custom.html` перед `<h3>` карточки добавить:

```html
{{ with .Params.icon }}
  <img src="{{ . | relURL }}" alt="" class="h-8 w-8 mb-4 text-primary-400" loading="lazy">
{{ end }}
```

Или, для лучшей интеграции с Blowfish, использовать встроенные SVG-иконки через `icon` shortcode в контенте, а не в шаблоне.

#### Оптимальная структура homepage (рекомендуемая)

1. **Hero** — фоновое изображение (heroStyle: background) + заголовок + 1 CTA
2. **Stats** — 4 счётчика (без изменений, работают хорошо)
3. **Services** — 2x2 карточки **с иконками**
4. **Advantages** — 4 карточки (без изменений)
5. **Partners** — grid **с логотипами**
6. **FAQ** — accordion shortcode (сворачиваемый)
7. **CTA** — финальный призыв (один, не дублировать hero)

Убрать: Topic Tags секцию, Platform CTA (вынести в навигацию).

## Шаг 3. Каталог услуг и проекты

### 3.1. Текущее состояние — List Pages

**Услуги** (`/services/`): `cardView: true`, без hero, с breadcrumbs, summary.
**Проекты** (`/projects/`): аналогичная настройка.

### 3.2. Диагноз

| Проблема | Влияние | Тип |
|----------|---------|-----|
| **Services карточки показывают «1 января 1г.»** — дата по умолчанию для страниц без `date` в frontmatter | Выглядит сломано, подрывает доверие B2B-клиента | 🔴 Критическая |
| **«76 слов · 1 минута»** в карточках услуг — метрика для блога, не для services | Не релевантно для каталога услуг | 🟡 Значительная |
| **Services не отсортированы по weight** — «Представительство» первая, а должна быть «Поставка оборудования» (weight: 1) | Неправильный порядок на list-странице | 🟡 Значительная |
| **Нет hero-изображений** на services list и projects list | Пустые белые/тёмные карточки без визуального различия | 🟡 Значительная |
| **Projects карточки — тоже «1 января 1г.»** — нет реальных дат | Аналогичная проблема | 🔴 Критическая |
| **Summary в карточках показывает markdown-символы** — «# RailTech выступает…» виден символ `#` | Blowfish берёт raw markdown в summary | 🟡 Значительная |
| **Нет hero на list-страницах** — `showHero: false` в глобальном `[params.list]` | Пустые заголовки, нет визуального контекста раздела | 🟢 Рекомендация |

### 3.3. Текущее состояние — Single Pages

**Service single** (`/services/equipment-supply/`): стандартный article layout, ToC справа, breadcrumbs, заголовок + markdown-контент.

### 3.4. Диагноз — Single Pages

| Проблема | Влияние | Тип |
|----------|---------|-----|
| **«1 января 1г.» на single** — та же проблема с датой | Некорректное отображение | 🔴 Критическая |
| **heroStyle: basic** — без фонового изображения, голый текст | Для проекта с `image:` в frontmatter — неиспользованный потенциал | 🟡 Значительная |
| **Нет CTA внизу single-страницы услуги** — после текста просто заканчивается | Потеря конверсии: B2B-клиент прочитал — и некуда нажать | 🟡 Значительная |
| **Нет метаданных проекта** — client, year, scope, status есть в frontmatter, но нигде не отображаются | Упущенная возможность показать кейс | 🟡 Значительная |
| **Services не используют `features` из frontmatter** на single-странице | Список фичей виден только на homepage | 🟢 Рекомендация |

### 3.5. Рекомендации

#### Исправить дату на services и projects

Добавить `showDate: false` в frontmatter каждой service и project страницы. Или глобально для разделов через `_index.md`:

```yaml
# content/ru/services/_index.md
---
title: "Наши услуги"
description: "Полный спектр услуг для железнодорожной отрасли"
cascade:
  showDate: false
  showReadingTime: false
  showWordCount: false
  showAuthor: false
---
```

`cascade` в Hugo применяет параметры ко всем дочерним страницам секции — нативное решение без хардкода.

#### Добавить hero-изображения на list-страницах

В `hugo.toml` включить hero для list:
```toml
[params.list]
showHero = true
heroStyle = "background"
```

Затем добавить `background.jpg` в каждый `_index.md` page bundle или `featureimage` в frontmatter.

#### Сортировка services по weight

Blowfish по умолчанию сортирует по дате. Для services добавить в `_index.md`:

```yaml
cascade:
  date: false
```

Или убедиться, что каждая service имеет `weight` и front matter `date` убран.

#### Projects: героический вид с background

Для projects, у которых есть `image` в frontmatter:

```yaml
# в каждом project
showHero: true
heroStyle: "background"
featureimage: "/img/projects/b2b-platform.jpg"
```

Blowfish отрисует hero с фоновым изображением автоматически.

#### CTA внизу single-страниц

Добавить в конец markdown каждой услуги через Blowfish shortcodes:

```markdown
---

{{</* alert icon="circle-info" */>}}
Для получения коммерческого предложения воспользуйтесь нашей B2B платформой или свяжитесь с менеджером.
{{</* /alert */>}}

{{</* button href="/contact/" */>}}Связаться с нами{{</* /button */>}}
{{</* button href="https://b2b.railtech.uz" target="_blank" */>}}Открыть каталог{{</* /button */>}}
```

## Шаг 4. Навигация и микро-взаимодействия

### 4.1. Текущее состояние

- Header: `layout = "basic"` (Blowfish default)
- Меню: 6 пунктов (О компании, Услуги▼, Проекты, Платформа▼, Блог, Контакты)
- Услуги: 3 подпункта (Инжиниринг, Консалтинг, Поставки) — только RU
- Платформа: 3 подпункта (Каталог, Закупки, Аналитика) — только RU
- Footer: описание + адрес + «Экосистема» links + социальные иконки + legal

### 4.2. Диагноз

| Проблема | Влияние | Тип |
|----------|---------|-----|
| **Подменю есть только у RU** — EN и UZ не имеют dropdown для Услуги и Платформа | Навигационная асимметрия между языками | 🟡 Значительная |
| **6 пунктов + язык + поиск + тема** = 9 элементов в header | На границе перегрузки, при 3 языках может быть тесно | 🟢 Незначительная |
| **Подменю «Платформа»** ведёт на внутренние страницы (catalog, deals, admin), но это B2B-платформа на отдельном домене | Пользователь ожидает перехода на b2b.railtech.uz, а попадает на информационные страницы | 🟡 Значительная |
| **Нет иконок в навигации** — все пункты текстовые | Для B2B-каталога с техническим контентом визуальная навигация помогает быстрому скану | 🟢 Рекомендация |
| **Footer «Экосистема» ссылки** на b2b.railtech.uz и cabinet.railtech.uz — единственный путь к внешней платформе из footer | Недостаточно заметно | 🟢 Незначительная |
| **Нет breadcrumbs на About, Contact** — `showBreadcrumbs` включён для article, но не для всех страниц | Потеря ориентации на внутренних страницах | 🟢 Незначительная |

### 4.3. Рекомендации

#### Подменю для EN/UZ

Добавить в `hugo.toml` подменю для EN и UZ аналогично RU:

```toml
# Menu - English (добавить подменю)
[[languages.en.menu.main]]
name = "Services"
pageRef = "/services"
weight = 20
hasChildren = true

[[languages.en.menu.main]]
name = "Engineering"
parent = "Services"
pageRef = "/services/#engineering"
weight = 21

# ... и т.д. для UZ
```

#### Упростить навигацию «Платформа»

Вместо 3 подпунктов «Каталог/Закупки/Аналитика» (которые ведут на описательные страницы) — сделать «Платформа» прямой ссылкой на `/platform/` (overview) + одну CTA-кнопку «Войти в B2B» в header. Или убрать dropdown и оставить flat link.

#### Иконки в навигации

Blowfish поддерживает `params` в меню, но не иконки напрямую в пунктах меню. Иконки лучше использовать:
- На карточках контента (через frontmatter `icon`)
- В shortcodes внутри markdown

## Резюме

Сайт RailTech имеет **прочную техническую основу** — правильно настроенный Hugo + Blowfish, трёхъязычная поддержка, семантическая разметка, accessibility-основы. Основные проблемы лежат в **визуальной идентичности** (оранжевый цвет не соответствует отрасли), **контенте** (отсутствие визуалов: hero, логотипы, иконки) и **UX-деталях** (сломанные даты, дублирование CTA, неинтерактивный FAQ).

Все рекомендации реализуемы **исключительно через нативные инструменты Blowfish** (color scheme CSS tokens, hugo.toml params, frontmatter cascade, shortcodes). Никакого кастомного CSS с нуля, никаких переопределений базовой вёрстки.

Ожидаемый результат после всех фаз: корпоративный B2B-сайт уровня Siemens Mobility / Alstom — строгий, технологичный, с чёткой конверсионной воронкой.
